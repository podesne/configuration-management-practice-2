## Запуск и тесты

Нужен Python 3.11 или новее. Сторонних библиотек Python нет,
сборка не требуется. Команды выполняются из папки проекта.

```sh
sh run.sh --package org.apache.commons:commons-text:1.12.0
python3 -m unittest discover -s tests -v
```

На Windows используются `run.bat` и `python` вместо `python3`.
Напрямую программа запускается через `python3 -m src.main` с теми же
опциями. Переменная `PYTHON` задаёт интерпретатор для `run.sh`.

## Параметры

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--package` | Координаты `groupId:artifactId:version` | Обязательна |
| `--repo` | URL Maven-репозитория или путь к тестовому JSON | Maven Central |
| `--test` | Читать тестовый JSON вместо POM | Выключено |
| `--output` | Путь к PNG-файлу | `output/graph.png` |
| `--ascii` | ASCII-дерево на пятом этапе | Выключено |
| `--filter` | Исключаемая подстрока | Пустая строка |
| `--help` | Справка по опциям | Выход после справки |

Адрес Maven Central: `https://repo.maven.apache.org/maven2`.
В тестовом режиме имя пакета состоит из больших латинских букв.
Пути при запуске через `run.sh` отсчитываются от папки проекта.
Фильтр учитывает регистр и проверяет `artifactId`, в JSON проверяет имя.
Если фильтр исключает начальный пакет, программа сообщает об ошибке.
Ошибки параметров дают ненулевой код завершения.

## Чтение Maven

Зависимости берутся из XML-файлов POM по HTTP или HTTPS.
Программа разбирает пространства имён, родительские POM, свойства
`${...}`, `dependencyManagement` и импортируемые BOM.
BOM хранит согласованные версии зависимостей.
Документы повторно используются в пределах одного запуска.

Учитываются области `compile` и `runtime`; `test`, `provided` и `system`
исключаются. Необязательные зависимости начального пакета учитываются,
необязательные транзитивные зависимости пропускаются.
Диапазоны версий и неразрешённые свойства вызывают ошибку.
Автоматическая активация Maven-профилей не поддерживается.
HTTP-ошибки, тайм-ауты и повреждённый XML завершают запуск с ошибкой.
Для получения зависимостей Maven и сторонние библиотеки не используются.

## Тестовый репозиторий

JSON содержит все пакеты и списки их прямых зависимостей.
У каждого упомянутого пакета должна быть запись, даже без зависимостей.

```json
{"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}
```

```sh
sh run.sh --package A --test --repo examples/basic.json
sh scripts/check_graphs.sh
```

Обход в ширину (BFS) проходит по уровням с рекурсией.
Исключённые пакеты не обходятся. Общая зависимость остаётся в графе,
если доступна по другому пути. Вершины повторно не обходятся,
но связи, замыкающие цикл, сохраняются.
Полные Maven-координаты с версией задают отдельную вершину.
Разные версии одного пакета не объединяются. Полное разрешение
конфликтов версий Maven не воспроизводится.
`exclusions` исключает зависимости в соответствующей ветви обхода.

Для JSON разворачиваются связи всего файла, затем BFS находит пакеты,
которые прямо или косвенно зависят от указанного. Для Maven поиск
ограничен загруженным графом. Поиск всех потребителей во всём Maven
Central не выполняется. Начальный пакет в ответ не входит даже при цикле.

## Ветки

| Ветка | Этап |
| --- | --- |
| `main` | Параметры и минимальный прототип |
| `stage-2` | Прямые зависимости Maven |
| `stage-3` | Граф, фильтрация и тестовый репозиторий |
| `stage-4` | Обратные зависимости |
| `stage-5` | Mermaid, PNG и ASCII-дерево |

Каждая следующая ветка продолжает предыдущую. Специальный вывод
параметров относится только к первому этапу, прямых зависимостей
ко второму, обратных зависимостей к четвёртому.

## Функции

Аргументы и результаты описаны в строках документации функций.
Код находится в `src`, проверки в `tests`, примеры в `examples`,
сценарии запуска в `scripts`.

| --- | --- |
| `application.load_graph()` | Получить граф из JSON или Maven по параметрам запуска. |

| `config.check_package()` | Проверить точные координаты и вернуть их части. |
| `config.parse_config()` | Получить параметры из списка или из командной строки процесса. |
| `config.validate_config()` | Проверить совместимость и значения всех шести параметров. |
| `config.print_config()` | Напечатать все параметры в формате ключ-значение. |
| `config.validate_test()` | Проверить имя пакета и наличие файла в тестовом режиме. |
| `config.validate_url()` | Проверить базовый HTTP-адрес без авторизации и параметров. |
| `graph.read_test_repository()` | Прочитать JSON со списками связей и проверить все вершины. |
| `graph.filtered()` | Проверить подстроку в имени пакета с учётом регистра. |
| `graph.excluded()` | Проверить координаты по парам groupId и artifactId, включая *. |
| `graph.build_graph()` | Построить достижимый граф рекурсивным BFS по уровням. |
| `graph.visit_level()` | Обработать один уровень и рекурсивно перейти к следующему. |
| `graph.test_loader()` | Сделать загрузчик JSON с тем же интерфейсом, что у Maven. |
| `graph.print_graph()` | Вывести каждую вершину и список прямых зависимостей. |
| `graph.load()` | Вернуть зависимости пакета, сохранив порядок JSON. |
| `main.main()` | Вывести обратные зависимости и вернуть код завершения. |
| `maven.pom_url()` | Построить адрес POM по трём частям координат. |
| `maven.download_pom()` | Скачать POM с ограниченным временем ожидания. |
| `maven.project_properties()` | Собрать встроенные имена project, pom и parent. |
| `maven.managed_key()` | Получить ключ управляемой версии зависимости. |
| `maven.resolve_entry()` | Раскрыть поля записи и пары исключений. |
| `maven.effective_dependency()` | Применить управляемые значения и раскрыть свойства зависимости. |
| `maven.coordinates()` | Получить точные координаты, отвергая отсутствующую версию. |
| `maven.__init__()` | Задать базовый URL и необязательную функцию скачивания для тестов. |
| `maven.load()` | Получить модель POM, обнаруживая циклы родителей и BOM. |
| `maven.make_model()` | Собрать свойства, управляемые версии и зависимости с родителем. |
| `maven.parent_model()` | Загрузить родительский POM, если он указан. |
